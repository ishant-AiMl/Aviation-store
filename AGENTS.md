## Architecture rules

- Product catalog lives in code (`src/lib/catalog.ts`); orders store product name and price snapshots so bills never change when the catalog does.
- All pricing/return/cancel rules live in `src/lib/pricing.ts` and are covered by `src/lib/pricing.test.ts`; the server always recomputes totals from the catalog — never trust client totals.
- Customers have no accounts: public server functions in `src/lib/orders.functions.ts` gate access by order number + email or the order's private `access_key` (bill link), and use the admin client only inside handlers after that check.
- Order, invoice and return numbers are generated by database defaults/sequences, not app code, so they stay unique under concurrency.
- Store admin uses `user_roles` + `has_role`; the first account to sign up becomes admin via an `auth.users` trigger. Admin server functions in `src/lib/admin.functions.ts` run as the signed-in user so RLS enforces access.
- Cart is client-only (localStorage) until checkout.
